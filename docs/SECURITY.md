# 安全设计与上线检查

## 已实施

- 统一 sessionStorage 会话，不混用 localStorage。
- Access Token 临近过期时通过 Refresh Token 刷新。
- 所有写接口使用 Zod 或等价运行时校验。
- 正式评分器由服务端根据冻结项目确定，拒绝客户端 graderId。
- 练习锁、考试时间、迟到窗口、截止时间和宽限期以服务器时间为准。
- 正式试卷不回退练习库。
- 交卷使用事务、行锁、提交哈希和回执。
- 成绩发布前不向学员返回分数。
- 多机构对象级权限检查。
- DOCX 限制扩展名、MIME、大小和 ZIP 文件头。
- S3 数据库只保存 object key；受保护接口返回素材。
- 安全响应头、CSP、nosniff、SAMEORIGIN 和 Referrer Policy。
- 种子脚本无固定密码，生产必须显式提供管理员密码。

## 上线前必须完成

1. 轮换所有 Supabase、S3、Coze、image2 和 mimo 密钥。
2. 在目标数据库执行全部迁移并验证 RLS、索引和约束。
3. 配置允许的生产域名，收紧 CSP `connect-src` 和 `img-src`。
4. 对登录、导入、生成媒体、保存答案和交卷接口配置网关限流。
5. 使用真实学校管理员、教师、学员账号完成越权测试。
6. 备份数据库和对象存储，演练恢复。
7. 禁止公开开发种子账号；首次登录强制改密。
8. 进行依赖漏洞扫描和容器/平台安全检查。

## 威胁模型重点

- IDOR：所有 schedule、paper、score、cohort、question、asset ID 均需机构或所有权校验。
- 答案泄漏：答案键只存在服务端冻结记录，API 不返回。
- 客户端篡改：分值、评分器、题型、截止时间均不信任客户端。
- 重复交卷：相同提交返回原回执，不同提交返回冲突。
- 断线：先保存再交卷；自动提交失败时保留服务端快照和异常日志。
